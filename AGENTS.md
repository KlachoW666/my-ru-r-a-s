# Kaban.gg / titanrust.ru

Правила этого проекта. Подробности — в [docs/](docs/), состояние работы — в [save/](save/).

## Порядок работы

Начинать с графа знаний, а не с grep:

```bash
cd /d/NewCasesRust && graphify query "<вопрос>"
```

Диагностировать строго по цепочке: **данные в SQLite → ответ API (curl) → фронт**. У каждого слоя есть тихий откат на мок, поэтому «на сайте не то» гораздо чаще означает «SELECT вернул 0 строк», чем «сломан рендер».

## Что перевешивает установленные скиллы

В `~/.Codex/skills/` подключены сторонние наборы (ui-ux-pro-max, marketingskills и другие). Они общие, а этот проект — нет. Где расходятся, действует правило проекта.

**Дизайн.** Своя система описана в [docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md) и она главнее любых готовых палитр и стилей из `ui-ux-pro-max`. Коротко: только токены, никаких литеральных hex; акцент — лайм `#b2ff00` и производные `--accent-*`; фоны тёплые (R>G>B), нейтральный серый в палитру не вписывается; глубина — внутренними тенями `--surface-inner-*`, не наружным `box-shadow`; переходы `--ease-ui` 0.15–0.2 с. Цвет предмета берётся из `rarity`, руками не задаётся. Светлой темы на сайте нет. У админки **другая** система (shadcn/zinc/Geist) — лайм туда не переносить.

Прежде чем брать палитру или шрифтовую пару из скилла, проверить, что она не спорит с этим. Обычно спорит.

**Правка UI.** Исходников Vue в репозитории нет: `public/assets/` и `admin.titanrust.ru/public/assets/` — собранный бандл. Править в нём можно, но при следующей сборке затрётся, и об этом надо предупреждать. Контракты фронта снимаются с бандла, а не угадываются.

**Тексты.** `stop-slop` полезен, но у документации проекта своя манера: по-русски, без канцелярита, каждое утверждение подкреплено проверкой. Не переписывать под общий шаблон.

## Правила при правках

**API.** Полезная нагрузка всегда в `data`: `{status:"success", data:{…}}`. Три эндпоинта — исключения, они описаны в [docs/API-MAP.md](docs/API-MAP.md).

**Порядок роутов.** Express берёт первый совпавший обработчик. Новые роуты — выше catch-all, литеральные пути — до параметрических. Если в ответе админки есть `catchAll: true`, обработчика нет.

**Деньги.** Сначала проверить, потом списывать. Начисление баланса живёт в одном месте на систему — `services/deposits.js`, `confirm()`. Ничего не начислять в обход него.

**Секреты.** Только через `.env`, он в `.gitignore`. В `.env.example` — пустые заглушки, не боевые значения. В админку секреты не класть.

**База.** Одна на весь проект: `admin.titanrust.ru/server/database.sqlite`. Схему создаёт админка. В git её нет и быть не должно — иначе `git reset --hard` на сервере затрёт боевые данные.
