# Вход в админку по паролю

После обновления `/login` принимает логин и пароль. `/register?token=…`
проверяет одноразовый инвайт и предлагает задать пароль (15–128 символов).
Роль берётся из приглашения, не из формы. Публичной регистрации нет.

Первый доступ владельца на сервере:

```bash
cd /var/www/bearz
sudo -u bearz node deploy/make-invite.js --role SUPER_ADMIN --hours 2 --url https://admin.bearz.top
```

Новых сотрудников владелец приглашает в разделе инвайтов. Для восстановления
пароля существующего сотрудника добавьте `--username ТОЧНЫЙ_ЛОГИН` к команде.
Привязанное приглашение сохраняет текущую роль, а установка нового пароля
аннулирует старые JWT-сессии и неиспользованные привязанные ссылки.
Не пересылайте ссылку посторонним и не публикуйте её в логах/скриншотах.

Миграция добавляет `password_hash` и `auth_version` в существующую SQLite-базу.
Поле `password` старой версии не используется для входа; `admin123` не работает.
Пароли хранятся как scrypt-хэши с отдельной случайной солью. Подбор ограничен
по IP и логину; лимиты в памяти одного PM2 fork-процесса сбрасываются при рестарте.
Новые JWT имеют отдельную audience админки; после обновления старую сессию
потребуется открыть заново. Сервер проверяет существование учётки, версию
сессии и актуальную роль при каждом защищённом запросе.

Существующий Passkey остаётся необязательным способом входа, скрытым под
«Другой способ входа». Новая регистрация Passkey отключена. В production
авторизация обязательна, даже если ошибочно указать `ADMIN_REQUIRE_AUTH=0`.

Формы — адаптер к собранному Vue-бандлу (`AdminPasswordPage.js` и CSS).
При появлении исходников перенесите их туда до пересборки.

Проверки: `node --test tests/admin-password-auth.test.js tests/admin-invite-contract.test.js tests/admin-keys-schema.test.js`.
Используются отдельная временная SQLite-база и локальный HTTP-сервер.
