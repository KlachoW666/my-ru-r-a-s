# Интеграция админки: рабочая шпаргалка

Дата проверки: 3 сентября 2026. Это промежуточный аудит, не подтверждение исправности всех разделов.

## Проверенный сценарий: баннеры

Связь компонентов:

```text
admin public/assets/BannersListPage-CxiREAQ9.js
  → admin-content-CSX1c7eT.js: GET/POST/PUT /banners
  → admin server/server.js → bannerRoutes.js
  → общая SQLite: banners
  → services/bannerContent.js
  → server.js: getLiveBanners()
  → GET /api/v1/banners → data.banners
```

Пути `admin public` и `admin server` выше относятся к `admin.titanrust.ru/`.

До исправления POST читал плоские поля вместо `content`, PUT возвращал успех без записи, а сайт подставлял фиксированные описания и подписи кнопок. Это воспроизведено тестом `tests/banner-contract.test.js`: сначала название в SQLite было NULL; после исправления админки тест отдельно выявил подмену описания на публичной стороне.

Теперь сервер сохраняет полный контент, выдаёт его форме и сайту, поддерживает деактивацию и порядок. Успешная пустая выборка больше не включает демонстрационные баннеры. При ошибке чтения БД прежний демонстрационный fallback в `getLiveBanners()` пока остаётся.

### API

Префикс админки: `/api/v1/admin`. Авторизация проходит через существующий `requireAdminJWT`; исправление баннеров не меняет настройки доступа.

| Запрос | Назначение |
| --- | --- |
| GET /banners?page=1&limit=100 | Список с `data`, `total`, `pagination` |
| POST /banners | Создание; возвращает `data: {id, content, sort_order}` |
| PUT /banners/:id | Замена content, необязательное изменение sort_order |

Тело создания и редактирования:

```json
{
  "content": {
    "title": "Название баннера",
    "isActive": true,
    "description": "Описание",
    "image": "/uploads/banner.webp",
    "buttonText": "Открыть",
    "buttonAction": "url",
    "buttonValue": "/cases"
  },
  "sort_order": 0
}
```

Обязательны непустой `title` и boolean `isActive`. `sort_order` — неотрицательное безопасное целое. Действия кнопки: `url` или `promo`; при заданном действии нужно `buttonValue`. URL принимает путь сайта либо HTTP(S). Необязательные строки: `mobileImage`, `video`, `mobileVideo`, `background`, `buttonColor`, `glowColor`, `borderColor`. Рамка — шестизначный hex, как требует текущая форма.

`content` заменяется целиком: отсутствие необязательного поля удаляет его. Отсутствие `sort_order` при PUT сохраняет порядок. Так работает кнопка Deactivate: форма передаёт весь content с `isActive: false`.

Ошибка данных — 400, отсутствующий ID — 404, ошибка БД — 500. Ответ ошибки: `{success:false,message}`. Денежные операции этот модуль не выполняет.

### Хранение и запуск

Общая БД: `admin.titanrust.ru/server/database.sqlite`. При первом запросе к баннерам админка проверяет схему и при необходимости добавляет `banners.content TEXT`. Старые строки не удаляются; для строк без JSON используется преобразование из `title`, `image`, `url`, `position`, `active`.

При записи JSON синхронизируются и старые поля. Публичная выборка продолжает фильтровать `active = 1`, сортировать по `position` и выдавать ID вида `banner-<id>`.

Перед применением к рабочему серверу нужна резервная копия SQLite и перезапуск обоих Node-процессов. В этой итерации серверы с рабочей БД не перезапускались; миграция проверена только на SQLite в памяти. Бандлы фронтенда не изменялись.

### Проверки

Из корня проекта:

```powershell
node --test tests/admin-keys-schema.test.js tests/banner-contract.test.js
```

Оба теста прошли. Тест баннеров использует реальные Express-обработчики и SQLite в памяти: проверяет старые строки, запись формы, чтение списка, функцию выдачи публичному сайту, замену полей, деактивацию, пагинацию, неизвестный ID и отклонение некорректных запросов без новых строк.

Тест изолированно извлекает блок регистрации из server.js, чтобы не запускать рабочие сервисы и не читать .env. Это не браузерный E2E и не полный запуск серверов.

Остаётся вручную проверить форму, загрузку изображений/видео, отображение на мобильном экране, открытие ссылок и применение промокодов. Совпадение сохранённых полей с выдачей сайта уже проверено, работа всех визуальных действий — ещё нет.
