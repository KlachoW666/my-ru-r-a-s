# Что не удалось сделать без исходников и новых ассетов

Список того, что упирается либо в отсутствие исходников Vue, либо в отсутствие
готовой графики. Всё остальное по ТЗ SATCHEL сделано — см.
[docs/SATCHEL-REBRAND.md](docs/SATCHEL-REBRAND.md).

## Нужны графические ассеты

Приложенный `SATCHEL_VISUAL_GENERATION_BRIEF.md` описывает набор изображений.
Реально переданы только два из них: **20 артов кейсов** и **токен валюты**.
Остальное пришлось либо выводить из этих двух, либо оставить.

### 1. Hero satchel — нет

Бриф (раздел 3) требует отдельный объект 2400×2400 и варианты
`satchel-unlit` / `satchel-ignited`. Их нет.

Сейчас hero-блок на главной **пуст**: он рассчитан на Spine-анимацию (см.
пункт 3), а не на статичную картинку.

Что нужно: `satchel-hero.webp` 1600×1600 и 900×900, прозрачный фон.

### 2. Четыре иллюстрации разделов — нет

`section-cases.webp`, `section-upgrade.webp`, `section-battles.webp`,
`section-rewards.webp` (бриф, раздел 6). Блока «четыре раздела LIGHT / IGNITE
/ BLAST / LOOT» на главной сейчас нет вовсе, и добавить его без исходников
Vue нельзя — это новый компонент, а не перекраска.

### 3. Spine-анимация персонажа — сломана до ребрендинга

`landing-*.js` инициализирует `init("titanrust", …, pathPrefix:"/spine/titanrust1/")`.

**Каталога `public/spine/` в репозитории нет вообще.** То есть анимация
отдаёт 404 и сейчас, и до ребрендинга. Путь намеренно не переименован:
переименование ничего не чинит, а потерять рабочую ссылку, если ассеты
где-то есть, легко.

Что нужно: либо Spine-бандл SATCHEL с теми же контрактами состояний, либо
решение отказаться от анимации и заменить hero статичным объектом (тогда
нужен пункт 1 и правка компонента — то есть исходники).

### 4. Ролик промо-баннера — отключён

`assets/raffle/mega-loop.mp4` и `.webm` — ролик с кабаном прежнего бренда.
Перерисовать видео нечем, поэтому в `server.js` у баннера выставлено
`video: null`, и баннер показывает картинку, которая уже заменена.

Что нужно: свой короткий ролик либо решение оставить статичный баннер.

### 5. Состояния баттлов сделаны обработкой, а не отрисованы

`boar-ready` / `wait` / `locked` / `winner` / `loser` собраны из **одного**
исходника — токена валюты, — через свечение, обесцвечивание и затемнение.

Бриф просит для `waiting` «погашенный фитиль», а для `winner` — «раскрытый
loot». Так не сделать: фитиль занимает несколько пикселей и не отделён
маской, а раскрытого варианта объекта не существует. Различие сейчас — общее
тёплое против общего холодного.

Что нужно: пять отдельных рендеров устройства в тех же размерах
(180 / 180 / 180 / 1024 / 512).

### 6. Набор UI-иконок — не делался

Бриф (раздел 8) описывает 16 иконок в едином стиле. В бандле уже есть свой
набор; заменить его без исходников — значит переписывать десятки чанков.
Иконки перекрашены в фирменный цвет, форма прежняя.

## Упирается в отсутствие исходников Vue

### 7. Hero-текст и брендовые заголовки разделов

ТЗ требует на главной:

```
Eyebrow: SATCHEL.TOP
H1: ПОДОЖГИ ФИТИЛЬ
Subtitle: Открывай кейсы. Улучшай скины. Сражайся за главный дроп.
CTA: ОТКРЫТЬ КЕЙСЫ / ИСПЫТАТЬ АПГРЕЙД
```

и брендовые заголовки внутри страниц: Cases → **LIGHT**, Upgrade →
**IGNITE**, Battles → **BLAST**, Rewards → **LOOT**.

Сейчас hero-блока с таким текстом в бандле нет — это новая разметка, а не
строка в локали. Подменить существующие заголовки на латинские слова можно
было бы заменой строк, но это ухудшило бы понятность интерфейса, не дав
композиции, которую описывает ТЗ.

### 8. Метафора фитиля в открытии кейса и апгрейдере

`LIGHT IT` / `ПОДЖЕЧЬ` вместо кнопки открытия, горящий фитиль как индикатор
загрузки, локальная brass-вспышка на reveal, дым при неудаче апгрейда.

Кнопки и анимации живут внутри скомпилированных компонентов. Через CSS можно
перекрасить, но нельзя добавить новый элемент фитиля в разметку.

### 9. Тач-таргеты меньше 44×44

На 375×812 таких интерактивных элементов **22 из 50**. Это размеры,
заданные внутри компонентов; исправлять их слоем CSS — значит вслепую
раздвигать вёрстку. Дефект существовал до ребрендинга.

### 10. Тайлы кейсов и карточка каталога

ТЗ описывает карточку: арт занимает доминирующую часть, ember по нижней
границе при наведении, подъём без сдвига сетки. Текущая карточка — часть
бандла, её геометрия задана в скомпилированном компоненте.

## Данные, а не код

### 11. Двадцать кейсов не заведены в каталоге

Арты лежат в `public/assets/cases/satchel/` и описаны в `manifest.json`, но
**в базу не записаны**: ТЗ прямо запрещает писать в production-базу без
отдельного разрешения, а завести кейс — это не картинка, а цена, состав и
отдача.

Готов скрипт:

```bash
node deploy/import-satchel-cases.js              # план, ничего не пишет
node deploy/import-satchel-cases.js --apply      # подставить арты
node deploy/import-satchel-cases.js --create --apply   # завести кейсы
```

Сопоставление идёт по slug. Сейчас в базе 5 кейсов с другими слагами,
поэтому совпадений 0 и все 20 артов ждут своих кейсов.

После `--create` кейсы создаются черновиками без цены и состава — сервер их
открытие заблокирует, пока состав не задан в админке. Это защита, а не
ошибка.
