# Kaban.gg / titanrust.ru

Платформа открытия кейсов Rust. Корень проекта: `D:\NewCasesRust`.

## Первое, что нужно знать

**Это не один проект, а три части, которые связаны только через SQLite-файл.**

| Часть | Что это | Порт |
|---|---|---|
| `server.js` + `public/` | игровой сайт: Express-API + **собранный** Vue 3 SPA | 3101 |
| `admin.titanrust.ru/` | админка: свой Express + свой собранный SPA | 8080 |
| `services/` | `steamSync.js` (каталог скинов из Steam), `auth.js` (Steam OpenID) | — |

Единственная база — `admin.titanrust.ru/server/database.sqlite`. Админка в неё пишет, игровой сервер читает. Оба сервера поднимаются **отдельно**.

**Исходников Vue в репозитории нет.** `public/assets/` и `admin.titanrust.ru/public/assets/` — минифицированный бандл. Правка UI в бандле работает, но затрётся при следующей сборке; всегда предупреждай об этом.

## Порядок работы над задачей

### 1. Сначала спроси граф знаний, а не grep

```bash
cd /d/NewCasesRust && graphify query "<вопрос>"
```

Граф уже построен (`graphify-out/`, ~9500 узлов). Он быстро отвечает на «какие файлы связаны» и «где лежит X». После правок кода: `graphify update .` — быстро и без затрат на LLM.

Оговорка: фронт минифицирован, поэтому имена узлов часто выглядят как `ut()`, `Q()`. По графу находи **файл**, дальше ищи в нём grep-ом по строковым литералам (URL, ключи localStorage, тексты) — они не минифицированы.

### 3. Диагностируй по цепочке, а не с конца

Любая задача «на сайте не то» решается строго в этом порядке:

```
данные в SQLite  →  ответ API (curl)  →  фронт
```

Почти всегда проблема на первом шаге. У каждого слоя есть тихий фолбэк на мок, поэтому «неправильные данные» гораздо чаще означают «SELECT вернул 0 строк», чем «сломан рендер».

## Ловушки, на которые уходит больше всего времени

1. **`app.use('/api/v1', …)` на строке 848 `server.js`** — catch-all. Несуществующий путь отдаёт `200 {data:[]}`, не 404. Опечатка в URL маскируется под «нет данных». Новые роуты добавляй **выше** этой строки.
2. **Серия без кейсов не отдаётся вообще**, кейс с `archived=1` пропадает из каталога, но остаётся открываемым по прямой ссылке.
3. **Порядок роутов в админке.** Новые пути добавлять в `adminRoutes.js` ВЫШЕ catch-all, а литеральные (`/kyc/levels`) — до параметрических (`/kyc/:id`), иначе Express примет "levels" за id. Если в ответе `catchAll:true` — обработчика нет.
4. **Часть админки — заглушки** `{success:true,data:[]}`, которые в базу не ходят (promo, guardian, kyc, wallet, giveaways, …). «Сохраняет, но не сохраняет» — это они.
5. **Три системы имён редкостей** (Steam → `mapRarity()` → фронт). `INDUSTRIAL` и `CONSUMER` не покрыты и падают в серый.
6. **Правки в бандле затираются пересборкой.** Уже внесена одна: адрес WebSocket в `index-CBN0naXL.js` (бэкап `.bak`) — при получении исходников перенести туда же.
7. **Никаких query-строк на entry-скрипте** в `public/index.html`. `?v=…` расщепляет ES-модуль на две копии, приложение монтируется дважды и Vue уходит в бесконечный цикл в `removeFragment` — вечный спиннер на всех маршрутах. Уже наступали.
8. **`server.js` тянет sqlite3 из `admin.titanrust.ru/server/node_modules`** — снесёшь их, отвалится вся живая выдача сайта.

## Правила при правках

**Дизайн.** Только токены, никаких литеральных hex. Акцент — лайм `#b2ff00` и его производные `--accent-*`. Фоны **тёплые** (R>G>B), нейтральный серый в палитру не вписывается. Глубина — внутренними тенями `--surface-inner-*`, не наружным `box-shadow`. Переходы — `--ease-ui` 0.15–0.2 с. Цвет предмета берётся из `rarity`, руками не задаётся. Светлой темы на сайте нет. У админки **другая** дизайн-система (shadcn/zinc/Geist) — лайм туда не переноси.

**API.** Полезная нагрузка всегда в `data`: `{status:"success", data:{…}}`. Axios-мутатор фронта разворачивает ответ до тела, поэтому payload вне `data` фронт не увидит.

**Порядок middleware в `server.js`** фиксирован: роуты `/api/v1` → catch-all → статика по папкам → статика корня → SPA-фолбэк `app.get('*')`. Вставка не в то место просто не сработает.

**Секреты.** `STEAM_API_KEY`, `JWT_SECRET` и всё остальное — только через `.env` (в `.gitignore`, читается через `process.loadEnvFile()`). В `.env.example` кладутся пустые заглушки, не боевые значения.

**База.** Схему создаёт и мигрирует админка (`initDatabase()`). Единственное исключение — `ensureAuthSchema()` в `services/auth.js`. Перед ручными `UPDATE`/`DELETE` останавливай админку, иначе `SQLITE_BUSY`.

## Запуск

```bash
cd D:/NewCasesRust && npm start          # сайт    → http://localhost:3101
cd D:/NewCasesRust && npm run admin      # админка → http://localhost:8080
cd D:/NewCasesRust && npm run sync-skins # обновить каталог скинов из Steam
```

Локальная разработка без реального Steam:

```bash
NODE_ENV= PUBLIC_URL=http://localhost:3101 ALLOW_MOCK_AUTH=1 npm start
```

## Что ещё не реализовано (не считай багом конфигурации)

- Инвентаря нет: выигранные предметы зачисляются деньгами, как мгновенная продажа.
- Предварительная фиксация серверного сида — раунды не хранятся, сид раскрывается сразу.
- Гонки: раздела нет в бандле и нет маршрута — на сервере это не решается.
- Два кейса помечены неверно настроенными, их состав правится в админке.
