# Грабли этого проекта

Каждый пункт стоил времени. Половину я нашёл, наступив второй раз.

## Порядок в Express — виновник большинства случаев

**Берётся первый совпавший обработчик.** Всё, объявленное ниже, не вызывается никогда.

Из-за этого ломалось:

- Настоящие роуты админки не работали, пока выше стояли 32 старые заглушки.
- Passkey-роуты не вызывались — были объявлены после `app.all('/api/v1/admin/*')`.
- Моки розыгрышей перекрывали новые роуты.
- `/config/games` и `/config/socials` отдавали захардкоженный список из `server.js`.

**Литеральные пути объявлять до параметрических.** `/kyc/levels` уходил в `/kyc/:id` с `id="levels"` и отвечал 404. То же было с `/bots/profiles`.

**Middleware применяется только к тому, что объявлено после него.** `app.use(attachAuth)` стоял внутри `registerAuthRoutes` на строке 1046, а игровые роуты — выше. Они не видели токен и работали как гость: предметы падали в инвентарь с пустым `user_id`, транзакции не писались, баланс не списывался. Симптом был странный — таблица `inventory` заполнялась, а выдача возвращала ноль.

Сейчас `attachAuth` стоит сразу после `express.json()`.

## Проверку прав нельзя вешать отдельным middleware

Соблазн: `app.use('/api/v1/admin', checkRole)`. В этом проекте так нельзя — по той же причине, по которой ломался `attachAuth`. Роут, объявленный выше, проверку не увидит и получит полный доступ, а заметить это можно будет только руками.

Поэтому проверка прав сидит **внутри `requireAdminJWT`**, который и так висит на каждом админском роуте. Забыть её невозможно: забыв `requireAdminJWT`, роут теряет и `req.user`, что видно сразу.

Проверять этот класс правок надо тем же способом: пройти все разделы каждой ролью и посмотреть, где 403. Один прогон — 58 путей, занимает секунды.

## Ссылка — это и есть пропуск

Фронт собирает ссылку на замес как `${location.origin}/crate-pvp/${battleId}` и кладёт в буфер. Отдельного поля под код приглашения в бандле нет, и добавить его на сервере нельзя — фронт его не пошлёт.

Значит, `uid` приватного замеса **и есть** секрет. Из этого два следствия, и оба обязательны:

1. Приватный замес не должен попадать ни в один список — иначе секрет виден всем.
2. `uid` должен быть длинным. Шесть байт для пропуска мало, у приватных теперь шестнадцать.

Прежде чем изобретать токен доступа, посмотри, какую ссылку строит бандл. Схема, которую фронт не умеет отправлять, просто ломает шаринг.

## Ответы, которые невозможно отличить

Catch-all в админке отвечал `{success:true, data:[], items:[], total:0}` — **байт в байт как пустая таблица**. Мой собственный аудит один раз ошибся из-за этого. Теперь catch-all добавляет `catchAll: true`.

Если в ответе есть это поле — обработчика нет, путь надо добавить в `adminRoutes.js` выше catch-all.

## Catch-all на игровом сервере

```js
app.use('/api/v1', (req, res) => res.json({ status: "success", data: [] }));
```

Несуществующий путь отдаёт **200 и пустой массив, а не 404**. Опечатка в URL выглядит как «данные не пришли». Новые роуты добавлять выше этой строки.

## Молчаливые фолбэки

У каждого слоя есть тихий откат на мок. «На сайте не то» гораздо чаще означает «SELECT вернул 0 строк», чем «сломан рендер». Порядок диагностики строго такой:

```
данные в SQLite  →  ответ API (curl)  →  фронт
```

## Форматы дат в SQLite

`CURRENT_TIMESTAMP` даёт `2026-08-23 13:55:32`, а `toISOString()` — `2026-08-23T14:56:37.516Z`. На 10-й позиции пробел против `T`, пробел меньше — **строковое сравнение всегда истинно**. Так 4330 предметов ушли в скрытые.

Не сравнивать даты строками. Использовать счётчик или `datetime()`.

## Bash съедает обратные кавычки

Патчи через `node -e "..."` с обратными кавычками внутри ломаются: bash подставляет результат выполнения. Документы записывались с дырами вместо кода.

Писать патчи **отдельным файлом** и запускать `node файл.js`.

## Порядок операций с деньгами

Сначала проверить, потом списывать. За отклонённое открытие кейса деньги всё равно снимались, потому что проверка состава шла после списания.

## Слияние веток и node_modules

`node_modules` были в индексе `main`, а ветка их оттуда убрала. При merge git **снёс файлы с диска**, серверы упали с `Cannot find module 'express'`.

Перед слиянием веток, меняющих отслеживание `node_modules`: остановить серверы, сделать бэкап базы, после слияния — `npm install` в корне и в `admin.titanrust.ru/server`.

## Файлы блокируются работающими серверами

`database.sqlite` и `node_modules/sqlite3/build/Release/node_sqlite3.node` держатся процессами. `git checkout` и `git merge` падают с `unable to unlink old`. Останавливать серверы перед операциями git.

## Контракты фронта сняты с бандла, а не угаданы

Три эндпоинта ждут форму, отличную от общего конверта `{status, data}`:

| Эндпоинт | Что читает фронт |
|---|---|
| `/live/recent` | `data.wins[]` — плоский массив даёт пустую ленту без ошибок |
| `/upgrader/items` | `items` и `pagination` на **верхнем уровне тела** |
| `/deposit-chain/state` | тир с полями `caseName` и `caseImage`, не `name`/`image` |

Блок депозита рендерится **только авторизованным** — `enabled: isAuthed && isDepositChainEnabled`. Гостю не покажется, что бы сервер ни ответил.

## Query-строка на entry-скрипте

`?v=2002` расщепляет ES-модуль на две копии: браузер кэширует модули по полному URL. Приложение монтируется дважды, Vue уходит в бесконечный цикл в `removeFragment`, главный поток встаёт — вечный спиннер на всех маршрутах.

Никогда не вешать `?v=…` на entry-скрипт Vite-бандла. Кэш и так сбрасывается хэшем в имени файла.

## Steam Market

- Размер страницы **жёстко ограничен 10**. `count=100` возвращает 10. Полный каталог — 543 запроса.
- **Валюта всегда USD.** `currency=5`, `country=RU`, `Accept-Language` и cookie `steamCountry` игнорируются.
- Пагинацию делать `sort_column=name`, иначе позиции переезжают между страницами прямо во время обхода.
- Безопасный темп ~20 запросов в минуту. Ниже 2000 мс между запросами — риск бана IP.
